#### 沒有改、但一併記錄的事

- 中選會第03選舉區名單上有 6 位，我們只有 5 位（缺 **林振德**，2022 當選）。
  那是「缺一筆」而不是「錯一筆」，屬於名單清查流程（`roster_check`）的範圍，這支不新增人物。
- `politicians` 表同 20 位的 `region` 也一起從台南市改成桃園市（`region_id` 不動，
  因為它指的就是上面那三列，列搬了就跟著對）。
- 統計：`regions` 的縣市層級列照這次異動的差額明確寫回
  （台南市 `representative_count` −20、`total_politicians` −20；桃園市 +20／+20），
  **不做整個縣市重算**。台南市現在的 `total_politicians`(1258) 跟五個分項之和(1239) 本來就差 19
  （立法委員進了總數、沒進任何分項），重算會順手把那 19 位洗掉，那是另一件事。

### 這筆資料是怎麼寫進去的

20 筆的 `source_note` 都是「中選會官方資料」、`verified_at` 都是 2026-01-31，
跟其他 5 個區（台中／新北／高雄，縣市都正確）同一批匯入。那條匯入路徑現在已經不在版控裡：
`pages/AdminScraper.vue` 在 #223（下架公開金鑰就能寫入的端點）被移除，而且它的選舉類型清單裡
根本沒有「直轄市山地原住民區民代表」——也就是說這 20 筆是當時某次一次性的手動匯入，
**現行程式沒有任何路徑會再寫出這種錯**，所以 A 段只修資料、不改程式。

值得記的是：`cec_candidates` 這張表的檔頭註解（2026-09-26）已經寫明
「20 筆縣市存錯（復興區被存成台南市）」。問題當時就被系統發現了，只是沒有任何東西會去改它。

## B. 2026 年 102 筆已登記的參選紀錄沒有地區

縣市議員 100 筆、縣市長 2 筆，`region_id IS NULL`。

### 縣市是怎麼推出來的

主要依據是 **`politicians.region`**——它跟這筆參選紀錄來自同一份貢獻 payload
（`apply-contribution.ts` 的 `ensureOrResolve` 會把 payload 的 `region` 寫進人物表），
所以它就是交件代理自己聲明的縣市。102 筆全部都有值。

旁證（獨立於 `politicians.region` 的第二來源）：

| 旁證來源 | 筆數 | 與 `politicians.region` 衝突 |
|---|---|---|
| `position` 字串本身帶縣市（「高雄市第10選舉區」「宜蘭縣第11選舉區」） | 60 | 0 |
| `current_position` 帶縣市（「嘉義縣議會議員」「新竹縣副縣長」） | 多數與上重疊 | 0 |
| `source_note` 的來源網址帶縣市代碼（`udn.com/vote2026/local_councilors?city=mlh` → 苗栗縣） | 多數與上重疊 | 0 |
| **至少一個旁證** | **74** | **0** |
| 無旁證（只有 `politicians.region`） | 28 | — |

「臺／台」兩種寫法都正規化成「台」再比。migration 在交易裡會再確認一次
`politicians.region` 還跟對照表一致，不一致就整支退回（資料被動過就不照舊值寫下去）。

### 只補到縣市層級，不猜選舉區

- **縣市長**的選區就是那個縣市，縣市層級本來就是對的形狀（2026 已經有 95 筆這樣指）。
- **縣市議員**的選舉區沒有可信依據可推：這批資料的 `position` 出現過
  「高雄市第12選舉區」～「第15選舉區」，但中選會 2022 高雄市議員只有第01～第11 選舉區
  （`electoral_district_areas` 與 `cec_candidates` 兩邊都是），而 2026 高雄市又在中選會
  「均建議維持本屆議員選舉區之劃分」名單內（<https://web.cec.gov.tw/central/article/61081>）。
  猜選舉區等於把來源不明的東西寫成已查證，所以只寫縣市。
- 畫面不會因此變差：`politicians_with_elections` 的 `subRegion` 是
  `COALESCE(per.sub_region, r.sub_region, p.sub_region)`，縣市層級列的 `sub_region` 是 NULL，
  會自動落回原本那一層，選舉區的顯示與篩選行為不變。

### 根因

`supabase/functions/_shared/apply-contribution.ts` 的 `applyCandidacy`：

```ts
async function districtRegionPatch(supabase, electionType, p) {
  if (electionType !== "縣市議員") return {};          // ← 縣市長一律走不到
  const district = str(p.electoral_district);
  const region = str(p.region);
  if (!district || !region) return {};                 // ← 沒填選區就回 {}
  const { data } = await supabase.from("regions")...;
  return regionId ? { region_id: regionId } : {};      // ← regions 沒那一列也回 {}
}
```

三個出口都是 `{}`，於是 `region_id` 落庫成 NULL，而且沒有任何訊息。
交件的代理拿到的回覆是「參選紀錄已建立為 registered」——看起來完全成功。

### 這次加的防呆

同一支 `apply-contribution.ts`：

1. `countyRegionPatch()`——縣市長／縣市議員，選區對不上時至少把 `region_id` 指到縣市層級那一列。
   既有紀錄已經有 `region_id` 的不動（不會把選舉區層級降級成縣市）。
2. `regionGapNote()`——連縣市都對不到時，回覆直接說「這筆還沒有對到地區，網站的縣市篩選撈不到他」
   並指出 region 填了什麼、該怎麼改；只補到縣市時也會說「先只記到縣市，請補 electoral_district」。
3. **刻意不涵蓋** `LOCAL_ELECTION_TYPES`（鄉鎮市長／代表／村里長／原住民區長／區民代表）：
   那幾種的「`region_id` 是空的」正是 `contribution_auto_tasks_township_gap`
   （`20261004000004_candidacy_township_gap.sql`）派「補鄉鎮」任務的訊號，補成縣市會把缺口藏起來。

測試在 `supabase/functions/_shared/district-region-apply.test.ts`（CI 的 `deno test _shared/` 會跑到）。
