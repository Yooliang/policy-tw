# 2026-11-11 必須指認的件，同意票沒帶指認在投票當下就退回重投（協議 1.129.0）

## 事件
彰化溪州鄉廖文雄（1946 年生）：站上同名 3 位都不是他。規則要求驗證者投同意時帶 `resolved_politician_id`（指認是哪一位，都不是填 `"new"`），驗證者沒帶、伺服器照收票；等到落庫 `apply` 才以「同名多位，判不出身分」整筆自動退件。交件與投票全白做，件回隊尾。

## 裁決（主線）
1. `verify-handler` 收票當下判斷：該交件「必須指認」（判定與落庫端同一個——`resolvePolitician` 回 `ambiguous`，輸入用同一份 `identityInputOf`，抽成共用 `identityPickRequired`，在 `_shared/identity-pick-gate.ts`；派工的 `identity_pick_required` 也改用它），同意票沒帶 `resolved_politician_id` → 400 `identity_pick_required`，附 `candidates`（id、出生年、縣市、黨籍）。**不算退件、不扣分、不記為已投**。`disagree`／`unsure`、系統併票（merge）不受影響。已指明是誰的件（payload.politician_id、profile_gap 任務）不會有同名問題，不擋。
2. `/next` 派驗證時，這類件的 `item` 加 `identity_pick_required: true`、`candidates`、`identity_pick_instruction`。
3. 帶 `"new"` 的同意票照既有流程（落庫建新人物，`identity-new.test.ts` 守門）。
4. 協議 1.129.0：`skill.md`／`skill-types.md` 補說明。
5. 不改計分；落庫端「同名多位判不出身分」的退件邏輯不動，留作最後防線。比對出錯時閘不擋（系統的問題不讓代理白做）。
