- **派工優先在選舉年之外，再依選舉類別提前固定天數，做成設定（2026-11-14，維護者裁示，不升協議版，`20261114010000`，守門 `election-type-priority-days.test.ts`）**：維護者 11-14 問「層級（縣市長／議員／代表／村里長）會不會加減優先」，答案是不會（只有選舉年與規則秒數）；裁示做成設定，改數字不改程式。
  - 做法：`queue_settings.election_type_priority_days`（JSONB，鍵＝職位中文名，值＝提前天數，沒列＝0）；`priority_seconds` 在「選舉年優先」之後再加 `election_type_priority_seconds(target)`＝天數 × 86400。排序鍵不動。預設：縣市長、直轄市長 6；縣市議員、直轄市議員 4；鄉鎮市長、直轄市山地原住民區長 3；鄉鎮市民代表、直轄市山地原住民區民代表 2；村里長 0；其他職位 0。
  - 職位怎麼對上：`target.election_type`，沒有就用 `target.politician_id`＋`target.election_id` 查 `politician_elections`；對不上（網站請求、名冊、基本資料…）加 0。寫入點與選舉年優先同一批：`seed_auto_task_queue()`、`contribution_tasks_insert_dispatch()`；驗證票沿用母任務位置，已凍結基準的現有驗證票不回頭改。
  - 改數字：`UPDATE queue_settings SET election_type_priority_days = '{…}' WHERE id = 1`，下一輪 seed（10 分鐘）既有派工列自動換秒數。
  - 理由：跨屆差距每屆 200 天以上，職位最多 6 天，所以選舉年仍是第一順位，職位只在同屆內決定先後。日本站不跟。
