- **人物一覽 `/politicians`（依姓氏筆畫分組，各組一頁 `/politicians/:筆畫數`）、政黨一覽 `/parties` 與各黨頁 `/party/:id`（#346 第一階段畫面）**｜做了什麼：①**人物一覽**：一萬六千多位人物（含全台村里長）依姓名第一個字的筆畫分組（台灣名冊「依姓氏筆畫」的慣例；日本站是五十音），索引頁列每一組有哪些姓、幾位，分組頁一個姓一段、姓名是連到人物頁的真連結，每位附一行說明——**現任職稱只來自任期**（`officeTitles`），沒有現任公職的寫最近一次參選（「2022 台南市議員・落選」，最近一次與年份照投票日、不照 id），同名的人才分得出來。筆畫數不另存字表：用 ICU 中文筆畫排序裡每個筆畫數的索引標記（U+FDD0＋U+2800＋筆畫數）比大小，台灣寫法（陳 11、黃 12、顏 18）；漢字以外（原住民族語拼音等）歸「其他」。②**政黨一覽**只列正見收錄的人物裡有人屬於它的政黨，**依名稱筆畫排、不依人數或席次**；無黨籍不是政黨、不列；名冊查無此名稱的另一段。③**各黨頁**：基本資料（簡稱、政黨編號、名冊狀態、成立日期、前身／改名為、出處連到內政部政黨名冊）、現職首長、現職民意代表、歷屆參選人（每一屆、每一種職位），同一塊依職位位階、地區、姓名筆畫排，**不排名、不依當選與否**；人很多的一組預設收合（`<details>`，內容與連結照樣在預渲染的 HTML 裡）。**第一階段依人物目前登記的政黨**（`politicians.party` 經 `party_aliases` 對照，跟資料庫 `politicians.party_id` 同一條規則、跟選舉頁卡片同一個依據），頁面上講明；參選紀錄的 `party_id` 補齊後第二階段改照當時的政黨列。④**收錄**：四種頁都預渲染（網址全是 ASCII）、進網站地圖、canonical 指正見.tw；組名或政黨 id 認不得的回 noindex；`firebase.json` 對 `/politicians/**`、`/party/**` 加回殼（200＋noindex），建置之後才出現的新政黨不會 404。頁尾「選舉」欄加「人物一覽」「政黨一覽」兩個連結（全站每頁頁尾多兩個連結，這是預渲染比對裡唯一的全站差異）。⑤**資料怎麼進頁面**：名單在建置端從整份人物資料算好（`lib/people-directory.ts`、`lib/party-pages.ts`，純函式、有測試）、只放進那一頁的快照；瀏覽器端不重算（要一萬六千位的參選紀錄與任期）——從站內別頁換頁進來沒有快照，就整頁載入預渲染那一份（`lib/full-load.ts`；直接打開網址還是沒有就講「還沒產生」，不會一直重載）；頁尾與頁內互連用一般連結，少一次換頁。政黨表在 migration 還沒套上的那一次建置用 `lib/party-seed.json`（跟 migration 資料段同一份）｜為什麼依筆畫不依注音：候選人名冊、選舉公報都依姓氏筆畫，讀者熟；注音要另一份字音資料、破音字還得人判斷｜為什麼不每個姓一頁：276 個姓、大半只有一兩位，一頁一姓是 276 頁薄頁；依筆畫 22 頁，最大一組（十一畫，3,681 位）HTML 約 1 MB，跟最大的鄉鎮頁同一級｜錯了的代價：名單要等下一次合併建置才更新（跟縣市頁一樣）；最大一組與國民黨頁各約 1 MB；一行說明與政黨頁的狀態字：**投完票的只講結果**（當選、落選、不參選），結果還沒補上的寫「…參選人」「結果待補」——不照人物頁寫登記階段的「表態參選」（2022 早期匯入的人狀態多停在 confirmed，其實在選票上），兩邊講法暫時不同，#345 第二階段人物頁改讀 `candidacy_status` 時統一；政黨頁照人物目前的政黨，換過黨的人過去的參選也列在現在的黨底下，頁面有講。
