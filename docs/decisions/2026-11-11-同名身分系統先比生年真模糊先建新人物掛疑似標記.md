# 2026-11-11 同名身分：系統先比生年，真模糊先建新人物掛疑似標記；身分退件改待指認不丟隊尾（協議 1.130.0）

## 起因
#920 把「必須指認」提前到投票當下擋，但判斷仍大量丟給代理：連同名者生年全都不同（明顯不是同一人）也要代理指認，缺生年才真的無法判斷的件也一樣卡住。維護者 2026-11-11 裁示「排吧」。

## 裁決（維護者）
**第 2 層：系統先判，不把判斷丟給代理。**
1. 交件（`candidacy`／`politician`）帶生年、站上同名者**全部**有生年且全不同 → 不是同一人，系統直接判新人物（`identityPickRequired` 回 false、落庫走 new）。生年相同者照既有規則比對。
2. 只有「有同名者缺生年」才真模糊。模糊時**先建新人物上線**，新人物標 `politicians.possible_duplicate_of`（缺生年同名者的 id 陣列）；人物頁顯示「疑似同人，待補生年」。判定在 `decide()`（`_shared/politician-identity.ts`），`flag=possible_duplicate`；仍有同名者生年相同、或命中的不是同名者時，維持 ambiguous。
3. 標記一建立，`duplicate_politician` 臂（`contribution_auto_tasks_dup`）就多一個配對條件「同名＋標記指到對方」，開合併任務，代理查官方資料決定 `same_person` true／false。缺生年那位的 `profile_gap` 由既有臂（當屆有參選紀錄、缺生年）負責，不另開。
4. 任一方補上生年：兩邊生年不同 → 觸發器 `politicians_clear_possible_duplicate` 清掉標記；相同 → 標記保留，由合併任務處理（合併後舊列 `merged_into`）。
5. 名冊對帳（`roster_reconcile_rows`）：名冊（鏡像有出生年）與全庫同名者都有生年且全不同 → 不算同名衝突，照「沒有同名者」處理（`missing_creatable`／new）。更正 2026-10-20 名冊對帳「同名即派代理」的範圍。**merge 限制不動**（同屆參選紀錄對不起來的兩位不得合併，2026-11-07）。名冊「同名者缺生年」的模糊案仍派代理（本次不做建新人物掛標記）。

**第 3 層：身分原因退件不丟隊尾。**
6. 落庫端因「同名多位判不出身分、驗證者未指認」要退件時（人票驗成的件，沒有系統驗證者簽名），交件**不轉 `rejected`**，改回 `pending`、標 `contributions.needs_identity_pick=true`，並重發驗證票（`task_dispatches` 的 `verify:<id>`）；驗證池不因「分數已達標」濾掉它。既有票數與分數保留，補一張帶指認的同意票即再次 verified 並落庫。每件只改回一次，再判不出才照舊退件；只有真的被反對到門檻才 `rejected`。
7. 與 #920 閘門互補：閘門擋前面，這條接住漏網的。

## 共同
- 身分候選組法抽成 `_shared/identity-candidate.ts`（`identityFieldsOf`／`identityCandidateOf`），落庫端與閘共用，消除「重建一份、可能漂開」。
- 協議 1.130.0：`skill.md`、`skill-types.md` 各補一段。migration `20261111170000`（只加不刪）。

## 錯了的代價
- 缺生年才建新人物：萬一其實是同一人，會暫時多一筆同名人物（掛標記、任務立刻開合併），比「卡住整件」輕；合併走既有 `merge_politician`。
- 名冊放寬：名冊生年或站上生年若有誤，可能多建一位人物；同單位的 `unm`／`sim` 安全網仍在。
